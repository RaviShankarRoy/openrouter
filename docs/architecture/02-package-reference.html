00 How to read this

Packages are grouped by service, then by tier. Within a tier they are listed in dependency order — the thing that depends on nothing comes first.

Each entry gives four things: purpose (one sentence on why the package exists), contents (the files and what each does), imports (what it is permitted to depend on), and used by (who depends on it). If you are adding a file, the tier it belongs to is determined by what it needs to import — see §07.

Tier legend

api delivery — speaks HTTP/CLI/React, converts between wire shapes and domain calls.
service business logic — use cases, entities, algorithms. Performs no I/O of its own.
repository mechanism — databases, caches, queues, HTTP clients, SDKs, generated code.
shared cross-cutting — config, logging, crypto, behaviourless types. Depends on nothing internal.

02 backend-python

The same four tiers, expressed as packages under app/. Python has no compiler-enforced visibility, so the rule is upheld by convention and review.

2.1 Entrypoints

ModulePurpose
app/main.py
102 lines		The FastAPI application. An @asynccontextmanager lifespan opens connections in order (logging → tracing → DB → Redis → NATS) and tears them down in reverse; create_app() assembles CORS, middleware, exception handlers, routers and the Prometheus mount. Also installs a SIGHUP handler that reloads routing.yaml, mirroring the Go gateway's behaviour so one operational gesture works on both services.
app/grpc_main.py
58 lines		The gRPC server, as its own process. Deliberately separate from the HTTP workers because the two scale on different signals — HTTP on request rate, gRPC on auth cache-miss volume. Same startup sequence, then serves until SIGTERM with a 5 s grace.

2.2 app/api/ — delivery api

ModulePurpose & contents
api/routes/
7 modules		One router per bounded context, registered with prefixes in __init__.py. health is unversioned (probes); everything else is under /v1. auth issues, lists and revokes keys. billing serves balance, top-up intents and usage. models is the catalogue. oauth exchanges a provider token for a backend JWT. webhooks takes Stripe callbacks. admin holds RBAC-restricted operations.
Every route declares separate request and response models, which is what keeps key_hash from ever being serialisable into a response.
api/dependencies.py
117 lines		Dependency injection. FastAPI's Depends() is the container — no third-party library. Provides a per-request Unit of Work, service factories, get_current_auth (bearer → SHA-256 → row → argon2 verify → AuthContext), and require_role(*roles), a dependency factory returning a closure.
hot spot get_current_auth runs a 64 MB argon2 verify inline on every call with no cache.
api/decorators.py
115 lines		Cross-cutting concerns. @require_permission checks a role→permission map and fails closed if no AuthContext is found among the injected kwargs. @audit_log writes an audit_logs row after the handler succeeds, in its own try/except so an audit failure cannot break a user request. Both use functools.wraps — without it FastAPI's signature introspection sees (*args, **kwargs) and injects nothing.
api/errors.py
66 lines		Error translation. Four handlers — domain errors, validation errors, HTTP exceptions, and a catch-all — all emitting the same OpenAI envelope. Domain errors log at info (they are expected outcomes); unhandled ones log a stack trace and return a generic 500 that leaks no class names or paths.
api/middleware.py
66 lines		Request context. Stamps a request id, binds it plus method and path into structlog contextvars for the request's duration, times the request, and echoes the id on the response. Also activates OTel auto-instrumentation for FastAPI and SQLAlchemy.

2.3 app/service/ — business logic service

ModulePurpose & contents
service/domain/
4 modules		The pure core — imports no framework at all.
entities.py: rich models with behaviour beside the data — APIKey.assert_usable(), assert_model_allowed(), CreditBalance.reserve()/settle(). The assert_* naming raises rather than returning a bool, so a caller cannot silently ignore the check.

service/billing_service.py
54 lines		Metering. Prices a request through the ModelPricing value object, deducts atomically, appends a usage row — all inside one Unit of Work. Cache hits cost zero, and that rule lives in exactly one place.
service/oauth_service.py
128 lines		Token exchange. Resolves the caller's email from Google or GitHub, find-or-creates a User and Organization, and mints a short-lived backend JWT. Uses GitHub's /user/emails rather than /user, because a profile email can be hidden but the emails endpoint always returns the verified primary.
service/uow.py
42 lines		The Unit of Work interface. Declares the transactional boundary the repository tier implements — six repositories sharing one session.
service/routing/
2 modules		Semantic routing for openrouter/auto. config.py loads and caches the candidate pool and implements filter() — capabilities, geography, residency, quality floor, latency ceiling — using set operations that read as the business rule they encode. reload_routing_config() validates before clearing the cache, so a broken YAML leaves the old config serving. strategies.py holds Cost, Latency and Quality strategies behind a registry.
service/guardrails/
2 modules		Input/output validation pipeline. pipeline.py is a Chain of Responsibility with three outcomes rather than two — pass, block (short-circuit), or redact (rewrite and continue), which is what makes it a pipeline. guards.py ships honest stubs (token limit, PII regex, injection phrases) each naming the real library it stands in for.
service/mcp/
3 modules		Model Context Protocol scaffolding. A server exposing gateway capabilities as tools, a client for calling external tool servers, and a per-org tool registry with federated OAuth. Interfaces only — Phase 4.

03 frontend-web

The same tiers, plus src/app/ which Next.js imposes. Six top-level folders in total.

FolderTierContents
src/app/api Routing, by Next.js file convention. Each folder is a URL segment. (marketing)/ is a route group — parentheses mean it does not appear in the path. Dynamic segments are [id], catch-alls [...path].
Two route handlers matter: api/auth/[...nextauth]/route.ts runs Auth.js and exchanges the OAuth token for a backend JWT in its jwt callback; api/proxy/[...path]/route.ts is the BFF — the browser calls it with an httpOnly cookie, and it attaches the real bearer server-side and streams the upstream body through unchanged so playground SSE survives.
dashboard/keys/actions.ts holds Server Actions ("use server") — server functions a form can post to directly, which work before JavaScript hydrates.
src/api/api The React delivery layer, in three groups. components/ holds one folder per feature — api-keys, auth, billing, models, playground, theme. layout/ holds composed page blocks (Sidebar, Topbar, UsageChart). ui/ holds the shadcn-style primitives (button, card, dialog, input, table, tabs, toast, badge, skeleton).
Server Components are the default; 'use client' appears only where state, effects, event handlers or browser APIs are genuinely needed.
src/service/service Client-side business logic. model/ holds the domain types (ApiKey, Model, Usage, User) that the UI speaks — deliberately camelCase, independent of the wire format. hooks/ holds stateful logic (use-clipboard, use-debounce, use-streaming-chat). providers/ holds the React context providers (Auth, Query, Theme). config/env.ts is the zod-validated environment, split into two schemas so the NEXT_PUBLIC_ boundary is enforced in code rather than by memory. types/index.ts is the barrel re-export.
src/repository/repository The transport layer. client.ts is the ApiClient: retry on idempotent verbs only, exponential backoff with jitter, a 30 s timeout, and W3C traceparent injection on the server side. api-key.ts, model.ts, usage.ts, user.ts are typed fetchers that also normalise the wire format — input_per_million becomes inputPerMillion — so no component ever branches on transport conventions. errors.ts holds the typed error classes; generated/schema.ts is the OpenAPI codegen output.
src/shared/shared cn.ts (class-name merging), format.ts (money, tokens, dates), logger.ts (pino).
src/types/shared next-auth.d.ts — module augmentation declaring backendJwt, userId, orgId and role on Session, so server actions read them without casting.

Root-level: middleware.ts is an edge auth gate that checks session-cookie presence only — deliberately cheap, with the real signature and role checks in the RSC layer. instrumentation.ts is opt-in OTel. next.config.ts sets standalone output and OWASP security headers (no CSP yet).

04 cli

FolderTierContents
src/cli.tsentryBuilds the commander program, applies global options (--json, --no-color, --debug, --base-url) and lets each command register itself. Runs main() only when invoked as the entry script, so importing it in a test does not execute the CLI.
src/api/api One module per command — login, logout, models, chat, usage, keys — plus output.ts for table and JSON rendering. Each exports a registerX(program) function, the same registry idea as the provider adapters.
src/repository/repository api-client.ts is the only file that knows the wire format, including SSE parsing. auth.ts is the most interesting file in the CLI: a CredentialStore interface with two implementations — the OS keychain via keytar, and an AES-256-GCM encrypted file with a scrypt-derived key for headless machines. Selection is by probing (call keytar once and catch the failure) rather than guessing from the platform. config.ts is XDG-compliant, zod-validated, and holds no secrets. version.ts reports CLI and Node versions.
src/shared/sharederrors.ts (typed error classes and exit-code mapping), logger.ts (pino).
What the CLI proves

It never talks to the backend, Redis or PostgreSQL. Every capability reaches it through the same public API a paying customer uses — which is the best available test that the public API is actually complete.

07 Import rules, and where new code goes

7.1 The matrix

From ↓ may import →apiservicerepositorysharedthird-party
apiyesyesyesyesyes
servicenoyesinterfaces onlyyesavoid
repositorynointerfaces onlyyesyesyes
sharednononoyesminimal

"Interfaces only" is the dependency-inversion seam. service/domain/repositories.py declares what persistence must do; app/repository/*.py implements it. The service tier depends on its own abstraction, and the repository tier depends on that same abstraction — so both arrows point inward and neither imports the other's concrete types.

The Go trick worth copying

When repository/adapters needed a ProviderConfig that service/router owned, the fix was not to relax the rule — it was to move the behaviourless shape into shared/model. Types with no behaviour create no coupling, so all three tiers can share a vocabulary without any of them importing another. If you hit the same wall, that is the move.

7.2 Where does my new code go?

You are adding…TierConcretely
A new HTTP endpointapiGo: a handler in api/handlers and a route in api/server. Python: a route module under api/routes/ plus a line in its __init__.py.
A new providerrepositoryIf it speaks OpenAI's format: a config block in providers.yaml and one line in the proxy's adapter map. If not: a new adapter file implementing the interface.
A new business ruleserviceOn the entity that owns the data if it is an invariant; in a service method if it orchestrates several entities.
A new routing algorithmserviceA file in service/strategies/ implementing Strategy. No existing file needs editing — that is the Open/Closed principle actually paying off.
A new background jobrepositoryA task in repository/tasks/, registered via the Celery include list. Make it idempotent — acks_late means at-least-once.
A new tablerepositoryAn ORM model, an Alembic migration, a repository implementation, and an abstract interface in service/domain/repositories.py — in that dependency order.
A new secret or settingsharedA field on the settings class, a line in .env.example, and — if it is deployed — an entry in the k8s secret or configmap.
A new UI screenapiA route folder under src/app/, components under src/api/components/, and a typed fetcher under src/repository/ if it needs data.
