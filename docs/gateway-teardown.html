00 What this is

An AI gateway: one OpenAI-compatible HTTP endpoint that fronts many LLM providers. A client points its SDK at your base_url instead of OpenAI's, sends the same JSON, and the gateway decides which provider actually serves it — translating request and response shapes, falling back when a provider dies, caching, rate-limiting, and metering the cost. That is the business OpenRouter is in, and this repo is a working skeleton of it.

The architecture splits along a latency boundary. Everything that must happen on every request lives in Go. Everything that can happen slowly, or once, or in the background lives in Python. The browser dashboard and the terminal client are TypeScript. The three talk over versioned contracts, never over shared code.

The organizing idea

Hot path vs. warm path. The Go gateway owns the request/response cycle and is stateless and DB-free — it is not allowed to open a SQL connection. The Python backend owns PostgreSQL exclusively and is the source of truth for keys, credits, usage, and pricing. Go reaches Python only when its caches miss. Every other design decision in the repo falls out of this one.

Read this document as a map, not a tutorial. Section 02 is the single most useful thing here — trace one request end to end and most of the rest becomes obvious. Section 11 is the master glossary of every pattern and technology in play. Section 12 is the honest state of the code.

1.1 Why a monorepo, and why polyglot

  • Monorepo — the .proto and .yaml contracts are shared, so a change to the wire format and both implementations land in one commit. Orchestrated with make, not Bazel.
  • Go for the hot path — goroutine-per-request concurrency, no GC pauses that matter at this size, cheap SSE streaming, single static binary in a scratch image.
  • Python for the warm path — the provider SDK ecosystem, tiktoken, Stripe, ML tooling, and Alembic migrations all live here.
  • TypeScript for humans — React Server Components for the dashboard, commander for the terminal.

02 The request path

One POST /api/v1/chat/completions, traced through every component that touches it. This is the spine of the whole system.

01RequestIDReads X-Request-ID or mints a UUID; stores it plus a start timestamp in context.Context. Echoes it back on the response.
02RecovererDeferred recover() converts a panic into a 500 in the OpenAI error envelope instead of killing the worker.
03LoggerOne structured slog line per completed request: method, path, status, duration. Never the body.
04TracingOpens an OpenTelemetry span named POST /api/v1/…, tagged with method, path, request id.
05AuthStrips Bearer , takes SHA-256 of the token, then a three-layer read-through cache: in-process map (~100 ns) → Redis auth:{hash} (~500 µs) → backend AuthService.ValidateKey over gRPC (~10 ms). Result is written back up every layer. Unknown keys get a short negative-cache entry so a key-guessing flood cannot hammer Postgres.
06RateLimitA Lua script evaluated atomically in Redis implements a sliding window over a sorted set: drop members older than 60 s, count, admit if under the per-key limit. Emits X-RateLimit-Limit/Remaining/Reset; a rejection is 429 plus Retry-After.
07ChatHandlerCaps the body at 10 MB, parses just model and stream. For non-streaming requests, computes SHA-256(model ‖ 0x00 ‖ body) and checks the L1 exact-match cache in Redis. A hit short-circuits with X-Cache: HIT.
08RouterLooks the model id up in providers.yaml (parsed once, held in an atomic.Pointer so SIGHUP can hot-swap it) and returns a primary target plus an ordered fallback chain.
09CircuitBreakerEach (provider, model) pair gets its own gobreaker instance. Five consecutive failures opens it for 30 s; it then half-opens and admits three probes. An open breaker skips straight to the next target.
10AdapterTranslates the canonical OpenAI request into the provider's native shape. OpenAI and OpenAI-compatible aggregators are passthrough; Anthropic gets a real rewrite — system messages hoisted out of messages into a top-level system field, max_tokens defaulted, x-api-key and anthropic-version headers set.
11providerSent on a per-provider http.Client with a tuned transport: HTTP/2 forced, keep-alive, bounded idle and per-host connections. 5xx or 429 counts as a failure and trips the breaker.
12StreamStreaming responses are read into a pooled 32 KB buffer from a sync.Pool and pushed through a per-request StreamTranslator, flushed after each chunk. The Anthropic translator is a real SSE state machine: it buffers partial lines, reassembles event:/data: pairs, and maps content_block_delta → OpenAI delta.content, message_delta.stop_reason → finish_reason, then writes data: [DONE].
13— designed —Emit a UsageEvent protobuf to NATS subject gateway.usage, off the request path. not built
14BillingServicePython consumes the event, prices it via ModelPricing.cost(), deducts credits with an atomic UPDATE … WHERE available >= amount, and inserts an immutable usage_records row. consumer not built

Steps 01–12 are implemented and compile. Steps 13–14 are designed — the proto exists, the Celery tasks exist, the BillingService exists — but nothing publishes the event, so the metering loop is open. See §12.

2.1 The two escape hatches

Two request shapes deliberately leave the Go path. model: "openrouter/auto" is meant to call Python's RoutingService.ResolveModel, which filters a candidate pool by capability, geography, and data residency, then ranks it with a pluggable strategy. Async video jobs and the model catalog delegate entirely to the backend. Both delegations are stubbed in Go today (they return 501), but the Python side of both is written.

03 Go gateway

3.1 Layered N-tier architecture

The layout is layered n-tier with dependency inversion between tiers. internal/ splits into four tiers — api/ (presentation: handlers, middleware, server), service/ (business: proxy, router, strategies, circuit breaker, rate limit), repository/ (data: auth loaders, cache, provider adapters, gRPC stubs) — plus cross-cutting shared/ (config, model, observability). Imports point downward only: api → service → repository, and any tier may import shared. internal/api/server/server.go is the single composition root — the only file that knows which concrete type satisfies which interface. cmd/gateway/main.go does nothing but load config, build a logger, start tracing, construct the server, and handle signals. Everything is constructor-injected, so any tier can be tested with a fake.

Chain of Responsibility
internal/api/middleware/ — each middleware is an http.Handler decorator. Order is declared once, in buildHTTPServer. Global middleware wraps everything; Auth and RateLimit are scoped to the /api/v1 subtree so /health and /ready stay open.
Read-through cache
internal/repository/auth/cache.go — a Loader interface with implementations tried in priority order. Adding a layer means appending a Loader, not editing the cache.
Strategy
internal/service/strategies/ — Cost and Latency both implement Order(ctx, []Target) []Target, resolved by name from a Registry. Cost sorts by a PricingLookup, latency by a ScoreLookup; both are interfaces so the data source is swappable.
Adapter
internal/repository/adapters/ — ProviderAdapter has four methods: Name, NormalizeRequest, NormalizeResponse, NewStreamTranslator. A separate translator instance per request holds per-stream state (message id, partial-line buffer).
Circuit Breaker
internal/service/circuitbreaker/registry.go — a lazily-populated concurrent map of sony/gobreaker instances keyed provider:model, built with double-checked locking so a hot key doesn't serialize on the write lock.
Object Pool
internal/service/proxy/pool.go — sync.Pool of 32 KB byte slices for streaming, plus a per-provider http.Client cache so TLS handshakes and connection setup amortize.
Copy-on-write config
internal/service/router/router.go — the parsed config lives behind atomic.Pointer[state]. SIGHUP parses a fresh file and atomically swaps the pointer; in-flight requests keep the old snapshot. No locks on the read path.

3.2 Configuration and lifecycle

koanf layers three sources in precedence order: hardcoded defaults → optional YAML file → environment variables prefixed GATEWAY_, where underscores become path separators (GATEWAY_HTTP_PORT → http.port). A validate() pass rejects a bad port, a missing Redis URL, or a missing backend address at startup — fail fast.

The process runs two listeners concurrently (API on 8080, Prometheus on 9091), each shut down by context cancellation. The signal loop distinguishes SIGHUP (reload provider config, keep serving) from SIGINT/SIGTERM (cancel, then a 30-second graceful drain).

3.3 Concurrency primitives in use

  • context.Context threaded through every call for cancellation and deadline propagation; a client disconnect mid-stream surfaces as context.Canceled and is swallowed rather than logged as an error.
  • sync.RWMutex for read-mostly maps (auth cache, breaker registry, client pool), always with a double-check after upgrading to the write lock.
  • sync.Once to lazily dial the backend gRPC connection, so an unhealthy backend cannot block gateway startup.
  • atomic.Pointer for lock-free config reads.
  • Buffered error channel + select to multiplex "a server died" against "a signal arrived".

3.4 Observability

slog emits text in dev and JSON in prod. OpenTelemetry exports over OTLP/gRPC with a ParentBased(TraceIDRatioBased) sampler — honor an upstream sampling decision, otherwise sample 1%. Seven Prometheus collectors are declared with deliberate label discipline: model, provider, status, cache_hit — never user_id or request_id, because unbounded label cardinality is how you kill a Prometheus server.

04 Python backend

4.1 Three tiers, one dependency rule

Layered n-tier. Imports point downward only: api → service → repository, and any tier may import shared. The service tier reaches the data tier through the Port interfaces in service/domain/repositories.py, never by importing app.repository directly — so the business logic imports nothing from SQLAlchemy, FastAPI, or Redis.

4.2 Domain concepts

Entity
Has identity that survives attribute change. Organization, User, APIKey, CreditBalance, UsageRecord, VideoJob — pydantic v2 models with business methods, not anemic data bags. APIKey.assert_usable() and assert_model_allowed() put the invariants where the data is.
Value object
No identity, compared by value, immutable. Money, TokenCounts, ModelPricing — frozen slotted dataclasses. Money refuses to be negative at construction and refuses subtraction that would go negative; ModelPricing.cost() is pure arithmetic on Decimal, never float, because money.
Repository
Abstract base classes in domain/repositories.py named after business intent — find_by_lookup_hash, not select. Implementations in infrastructure/repositories/.
Data Mapper
ORM classes are kept separate from domain entities; each repository has a private _to_domain(row) translator. The schema can move without breaking domain code, and Alembic autogenerate stays clean.
Unit of Work
async with uow: opens one AsyncSession shared by every repository, so a multi-repository use case is one transaction. __aexit__ rolls back on exception and always closes. Commit is explicit.
Domain error hierarchy
DomainError subclasses each carry a code and an http_status. One FastAPI exception handler turns any of them into the OpenAI error envelope — expected errors log at info, unhandled ones log a stack trace and return a generic 500 that leaks nothing.

4.3 The two-hash key scheme

This is the most important security design in the repo. An API key sk-or-v1-{64 hex} is stored twice:

  • argon2id hash in key_hash — memory-hard (64 MB, 3 iterations, parallelism 4), deliberately slow, the at-rest defense if the database leaks.
  • SHA-256 hex in key_lookup — a fast, unique, indexed column used to find the row.

Validation is therefore two steps: index-seek on the cheap hash, then one argon2 verify on the candidate. You get a memory-hard hash without paying 64 MB of work per request lookup — and Redis caches the result so most requests pay neither. The plaintext is returned exactly once at creation and never stored.

4.4 Dependency injection and decorators

FastAPI's Depends() is the DI container — no third-party library. get_uow yields a per-request unit of work, get_current_auth resolves the bearer token into an AuthContext, require_role(*roles) is a dependency factory returning a closure.

Two decorators handle cross-cutting concerns. @require_permission("keys:write") checks a role→permission map and fails closed if it cannot find an AuthContext in the resolved kwargs. @audit_log(action, target_type) writes an audit_logs row after the handler succeeds, wrapped in its own try/except so an audit failure can never break a user request. Both use functools.wraps, which is what lets FastAPI still introspect the original signature for dependency resolution through the wrappers.

4.5 Provider adapters

The ProviderAdapter ABC declares complete, stream, count_tokens, health_check, and pricing over unified request/response dataclasses. OpenAIAdapter is the reference; GemmaAdapter and QwenAdapter subclass it and override three class attributes — provider name, base URL, API-key setting — because Fireworks and Together speak the OpenAI wire format. That is the whole cost of adding an OpenAI-compatible provider. AnthropicAdapter is a full rewrite against the Messages API. Registration is a singleton registry populated by a bootstrap.register_providers() factory.

Token counting is asymmetric on purpose: OpenAI uses real tiktoken encoding; Anthropic uses a len(chars) // 4 estimate, because their count endpoint is rate-limited and this is a hot-path estimate.

4.6 Routing, guardrails, jobs

Semantic routing
configs/routing.yaml holds a candidate pool: model, provider, price, quality score, p50 latency, capability set, allowed geographies, data-residency jurisdictions. RoutingConfig.filter() narrows by request hints; a RoutingStrategy (cost / latency / quality) ranks the survivors; a sentinel model catches the empty case. Reloadable on SIGHUP with validate-then-swap — a broken YAML leaves the old config serving.
Guardrail pipeline
Chain of Responsibility over text. Each Guardrail.check() returns pass, block, or redact; a redaction rewrites the payload and the chain continues with the new text. Token-limit, PII-regex, and prompt-injection guards ship as working stubs standing in for presidio / llm-guard.
NATS JetStream
Pub/sub for lossy, high-volume telemetry — the usage-event stream. Persistent, replayable, with a 24-hour retention window.
Celery
Durable jobs where loss is unacceptable: video generation (submit → poll → finalize), signed outbound webhooks with HMAC and ~10 h of exponential backoff, nightly billing aggregation. task_acks_late plus prefetch_multiplier=1 trades throughput for at-least-once fairness.
Cache-aside
PricingRepository reads Redis first, falls through to Postgres, writes back with a 60 s TTL, and exposes explicit invalidation.
MCP
Model Context Protocol scaffolding — a server exposing gateway capabilities as tools, a client for calling external tool servers, and a per-org tool registry with federated OAuth. Interfaces only; Phase 4.

4.7 The gRPC side

app/grpc_main.py runs the servicers as a separate process from the HTTP workers — they scale on different signals (auth-cache-miss volume vs. request rate). AuthServicer.ValidateKey resolves a key by lookup hash and returns policy plus budget; RoutingServicer implements ResolveModel and ProviderScores. Generated stubs are imported lazily inside try/except so unit tests run before make proto has ever been executed.

5.2 Server-first rendering

React Server Components are the default; 'use client' appears only where state, effects, or event handlers are needed. Pages compose independently-streaming <Suspense> boundaries so one slow query cannot block the shell. Mutations use Server Actions ("use server") — a form posts directly to a server function that validates with zod, calls the API, and calls revalidatePath, with no route handler in between.

5.3 The BFF

app/api/proxy/[...path]/route.ts is a backend-for-frontend: the browser calls same-origin /api/proxy/* with a session cookie, and the server exchanges that for a bearer token before forwarding to the gateway. Access tokens never reach client JavaScript. It streams the upstream body through unchanged, which is what makes playground SSE work.

5.4 Auth, config, and the API client

  • Auth.js v5 with a JWT session strategy. On first sign-in the jwt callback exchanges the Google or GitHub access token at the backend's /v1/oauth/exchange for an internal JWT carrying user_id, org_id, role, and stores it on the token.
  • Edge middleware gates /dashboard, /admin, /playground on session-cookie presence only — cheap. Real signature and role checks happen in the RSC layer.
  • zod-validated env split into a server schema and a NEXT_PUBLIC_* client schema, parsed at module load so a misconfigured deploy fails immediately.
  • ApiClient — a small transport with retry on idempotent verbs only, exponential backoff with jitter, a 30 s timeout, and W3C traceparent injection so browser spans chain onto gateway spans.
  • Vercel AI SDK useChat drives the playground's token-by-token rendering.

06 CLI

commander for the command tree, undici for HTTP, zod for config validation, tsup to bundle an ESM binary. Six commands: login, logout, models, chat, usage, keys.

The interesting part is credential storage, which is the Adapter pattern again. KeytarStore uses the OS keychain — Keychain on macOS, Credential Manager on Windows, libsecret on Linux. When that is unavailable (headless boxes, WSL, Alpine), EncryptedFileStore falls back to an AES-256-GCM file with a scrypt-derived key and 0600 permissions. Selection is automatic, probed by calling keytar once and catching the failure, and pinnable through config. Config itself follows the XDG spec via env-paths and holds no secrets.

Every command honors --json for machine output and NO_COLOR per the no-color.org convention.

7.2 OpenAPI — public

shared/openapi/openapi.yaml (OpenAPI 3.1, 478 lines) is the canonical description of the public surface: chat completions, models, embeddings, images, videos, audio transcription, rerank, health. FastAPI's auto-generated schema is explicitly not the source of truth. openapi-typescript generates the frontend's types; the CLI hand-mirrors the subset it consumes.

Both the error envelope and the endpoint shapes follow OpenAI exactly. That is the product: {"error": {"message", "type", "code", "param"}} everywhere, so an existing OpenAI SDK works after changing one string.

8.1 Concurrency-safe money

Two complementary mechanisms guard against overspend under concurrency. get_for_update() issues SELECT … FOR UPDATE, taking a row lock for read-modify-write sequences. deduct_atomic() avoids the lock entirely with a conditional update:

UPDATE credit_balances
   SET available = available - :amount
 WHERE org_id = :org_id
   AND available >= :amount   -- the invariant, enforced by the database
-- rowcount == 0  →  insufficient funds

The reserved column supports a two-phase pattern — reserve an estimate before the provider call, settle the actual cost after — so two concurrent expensive requests cannot both pass a balance check on the same funds. Alembic runs forward-only in production; the downgrade() functions exist for local resets.

09 Infrastructure

9.1 Local

docker-compose.yml brings up pgvector/PostgreSQL 16, Valkey 7 (the BSD-licensed Redis fork), NATS with JetStream, MinIO, Jaeger, and Ollama — every one with a healthcheck. A second file, docker-compose.observability.yml, adds Prometheus, Grafana, Loki, Tempo, and Promtail. A third, docker-compose.dev.yml, containerizes the app services themselves. The Makefile also offers a native path through a Procfile.dev.

9.2 Kubernetes

Raw manifests in base/, environment deltas in overlays/{dev,staging,prod} via Kustomize. The manifests are unusually complete and every non-obvious choice is commented in the file:

  • Pod Security Standards "restricted" — runAsNonRoot, uid 65532, readOnlyRootFilesystem, all capabilities dropped, seccompProfile: RuntimeDefault, with emptyDir volumes for the paths that genuinely need writes.
  • Topology spread constraints across zone and hostname so one AZ failure cannot take every replica.
  • Three probe types — startup, liveness, readiness — plus a preStop sleep so the endpoints controller removes the pod before SIGTERM, which is what prevents 502s during a rollout. 30 s grace on the gateway to drain in-flight SSE; 300 s on Celery workers for long media jobs.
  • HPA v2 scaling on a custom RPS metric and CPU and memory, 5→200 replicas, with asymmetric behavior: 30 s stabilization scaling up, 300 s scaling down, to avoid thrash.
  • No CPU limit on the gateway — a deliberate call, since CFS throttling would spike the P99 latency budget the service exists to protect.
  • PodDisruptionBudgets, NetworkPolicies, ServiceAccounts with automountServiceAccountToken: false, ServiceMonitor and PrometheusRule CRDs.

9.3 Helm and Terraform

The Helm chart targets two opposite deployments from one template set: values-prod.yaml for the SaaS, values-self-hosted.yaml for air-gapped installs. It integrates external-secrets.io with a Vault backend. Terraform (dev environment) composes upstream AWS modules into VPC across 3 AZs → EKS → RDS → ElastiCache → S3, with a single NAT gateway flagged as a dev-only cost saving.

9.4 CI

Four GitHub Actions workflows. ci.yml uses dorny/paths-filter to run only the stacks that changed, generates proto stubs before building, and runs go test -race, golangci-lint, pytest against real Postgres and Valkey service containers, and the frontend suite. Separate workflows handle Docker builds, Trivy scanning, and k6 load tests.

10.1 The non-negotiables

  1. The Go gateway never opens a SQL connection. If you reach for database/sql in gateway-go/, stop.
  2. Gateway↔backend is gRPC. HTTP/JSON is for admin tooling only.
  3. Python uses asyncpg, not psycopg3 — psycopg3 is LGPL-3.0, which is a problem for air-gapped distribution.
  4. No logging on the gateway hot path; usage telemetry goes to NATS asynchronously.
  5. Frontend defaults to Server Components.
  6. Never log raw API keys, prompts, or PII. The Python logger has a scrubbing processor as a last line of defense.
  7. Never label a Prometheus metric by user_id or request_id.

12 Reality check

The repo describes itself as a scaffold, and that is accurate. Here is what I verified by building, running, type-checking, and grepping — not by reading the docs.

12.1 Build and test status

StackResultDetail
gateway-go builds 1 test fails CGO_ENABLED=0 go build ./... succeeds. auth, cache, circuitbreaker, proxy/adapters pass. TestLimiter_ResetAtIsInTheFuture fails — not a production bug: miniredis's embedded Lua clamps the 64-bit millisecond timestamp to int32, returning -2147483648. I confirmed this with a direct probe. Real Redis returns 64-bit integers. The test needs a different assertion or a real Redis. 13 of 18 packages have no tests at all.

frontend-web 16 type errors tsc --noEmit fails. Details below.
cli not installed No node_modules; not exercised. Also absent from the root make test target.

12.2 Wiring gaps — code exists but nothing calls it

  • Provider registry is never populated. register_providers() is called only from a test, never from the FastAPI lifespan. GET /v1/models therefore returns {"data": []} in a running backend.
  • No usage events are published. The Go gateway has NATS config and a generated UsageEvent type but no publisher. Nothing consumes gateway.usage either. The entire metering and credit-deduction loop is disconnected from live traffic.
  • Prometheus metrics are declared but never incremented. All seven collectors in observability/metrics.go are defined and registered; no code path records a value. /metrics serves Go runtime stats only.
  • The L1 cache never fills. ChatHandler.Create reads the cache and has a TODO where the write-back should be — so every lookup misses forever.
  • Backend delegation returns 501. GET /api/v1/models and all three /videos routes are wired to a backendDelegate stub.
  • Routing strategies are unreachable from Go. strategies.Registry is never constructed; Router.Resolve returns the static YAML order.
  • Key revocation does not propagate. Cache.Invalidate exists on the Go side; the Redis pub/sub publisher and subscriber that would call it do not. A revoked key stays valid for up to the 60 s cache TTL.

Credential exposure

The committed .env contains a real Google OAuth client secret (GOCSPX-…). Treat it as leaked: rotate it in the Google Cloud console, delete the file from the working tree, and purge it from git history before this repo goes anywhere public. Use .env.example for new clones. Separately, SECRET_KEY defaults to "dev_only_change_in_prod_min_32_chars_long" and signs every JWT — it must be overridden by environment in any deployed setting.

12.5 If you want it running, in order

  1. Rotate the leaked OAuth secret; remove .env from the tree.
  2. Recreate the Python venv against an available interpreter and confirm the test suite runs.
  3. Fix the celery module path in the two k8s manifests.
  4. Call register_providers() in the FastAPI lifespan — one line that makes /v1/models real.
  5. Fix the frontend's 16 type errors; the path and token-name mismatches are the ones that block actual use.
  6. Wire the usage-event publisher in Go and a NATS consumer in Python. That closes the metering loop and turns billing from code into behavior.
  7. Record the Prometheus metrics that are already declared.
